# 05 地圖資料與手機技術 前期研究（2026-10-31）

方法說明：只用 WebSearch / WebFetch，沒有寫程式、沒有呼叫 Overpass。OSM 數字來自 **taginfo.geofabrik.de 的台灣區域資料庫**（網頁/統計端點，資料截至 2026-10-30 20:01 UTC）。標「推論」者為我的判斷，並非來源明文。標「未證實」者為只有論壇或第三方部落格的說法，請在實機驗證。

重要限制：taginfo 只有「全台灣」數字，查不到「台北市」單獨數字。

- 能做主力冷知識的：超商（品牌）、紅綠燈、公車站、廟、YouBike、i郵箱、飲水機。

- 推論：這些「路上日常物」不要依賴地圖資料點位。建議改成「情境式冷知識」：例如在任何一條路上，AI 以「附近道路 + 行政區 + 時間」說「你腳下的人孔蓋…」，或由使用者拍照後由視覺模型辨識。人孔蓋/電線桿冷知識可做成「通用知識庫」，不需點位。

建議做法：
- Demo 路線先挑 OSM 資料密的區域（例如西門、迪化街、艋舺、公館）並人工在 OSM 或自建 JSON 補 5～10 個 POI。
- 用 `amenity=place_of_worship` + `religion` 過濾廟；用 name 與 name:zh。

### 1.2 Overpass API 限制與替代方案

發現（OSM Wiki Overpass API 頁）：
- 主要實例 overpass-api.de 頁面自述「heavily used / overloaded」，不可靠，建議用替代。
- 輕度使用上限：每天 10,000 個 query 與 1 GB 下載，總處理時間 10 分鐘內。**「regular use 要除以 100」**，即約每天 100 query；網站/App 的所有使用者共用同一額度。
- 收到 HTTP 429 或 406 要等 30 秒。要送 User-Agent 或 Referer 辨識；快取、限速、不要平行腳本。
- Wiki 特別提醒避免用 lovable.app、netlify.app 這類快速部署平台（會被集體限流，原文是針對 AI 生成 app 的建議）。
- 第三方整理（非官方，未證實）：每 IP 2 個並行 slot；超限回 429。
- 其他：Overpass.ch 免費層 每月 1 萬請求、每分鐘 30；Geofabrik、Tracestrack 等商用服務有 key/免費層（細節未查）。
- 自架 Overpass 為 AGPL v3，可自行安裝。
- 大範圍建議下載 Geofabrik 區域 extract 再用 osmium 過濾（Wiki 說法）。Geofabrik 台灣 extract 路徑為 `download.geofabrik.de/asia/taiwan-latest.osm.pbf`（來源為 gist，檔案大小我沒查到）。BBBike 是否有台北 extract 未證實。

對專案的影響：若 App 每次走動都即時打 Overpass，多位評審同時用會很快撞到共用額度。

建議做法（推論）：**黑客松前一天預先抓台北 Demo 區域 POI 存成靜態 GeoJSON / JSON 打包進網站**，執行期完全不呼叫 Overpass；即時 GPS 只在本地用距離計算找最近 POI。如要更新，用 build 階段腳本（含 User-Agent 且一次性）取得。

### 1.3 台灣政府開放資料

- **TDX 運輸資料流通服務**：公車站位等「基礎」服務，不帶 API key 僅能用瀏覽器呼叫、每 IP 每日 50 次；進階/加值等需會員與金鑰。金鑰（Client Id/Secret）最多 3 組；token 端點每 IP 每分鐘 20 次；自 113 年 4 月 29 日起 API 呼叫上限依訂閱方案而定（具體數字我沒查到）。OIDC Client Credentials 認證，建議快取 token。公車站位屬哪個服務層級我沒確認。
- **政府資料開放平臺（data.gov.tw）**：
  - 臺北市路燈迴路開關箱資料（有 Latitude/Longitude），為工務局公園路燈工程管理處提供。
  - 臺北市公共管線圖資（路燈電力系統：開關、電桿等），XML、geometry 欄位，「僅供參考」。
  - 臺北市路燈維修資料（無座標）。
  - 人孔蓋：只找到「人孔蓋下地數量」統計，沒有座標。**沒找到台北市人孔蓋點位資料集**。
  - 便利商店：有「Taiwan Sugar 超商」、「前五大超商資料集」、「營業登記（便利商店）」等資料集（細節與是否有座標未驗證）。
- **內政部國土測繪中心**：村里界、鄉鎮市區界以 WMS/WMTS 網路地圖服務為主（EPSG:4326/3826/3857），授權為政府資料開放授權條款第 1 版、免費；沒確認有 shapefile 直接下載。
- **門牌位置資料庫**：內政部有全台約 800 萬筆門牌位置（2009 年建置）；TGOS 轉址使用 TWD97，要自行轉 WGS84。

對專案的影響：政府資料對「公車站」有幫助，但 OSM 已有 49k 公車站，可略過 TDX。路燈/電桿資料有台北開放資料可補強電桿冷知識（座標精度與格式要實測）。

建議做法：4 天內不碰 TDX；若想要「電線桿/路燈」點位，可下載台北路燈開關箱與公共管線圖資（需先看格式、座標系統）。

### 1.4 反向地理編碼（座標→行政區/街區）

- **Nominatim 公用服務**：絕對上限 **1 request/秒（整個應用合計）**；禁止 autocomplete；需有效 Referer/User-Agent；要快取；週期性請求算 bulk，不鼓勵。
- TGOS：沒查到可確認免費的反向地理編碼 API 規格。TGOS MAP API Lite 是網頁地圖標記用。
- 其他選項（推論）：自行用村里界/行政區界 GeoJSON 在客戶端做 point-in-polygon，最穩、免 API、可離線。街道名可從預載的 OSM way（highway + name）取最近道路。

建議做法：行政區用預載界線 polygon（本地計算），街名用預載的道路資料；完全避開 Nominatim 呼叫。

## 2. 定位

發現：
- 手機 GNSS 在都市峽谷主要問題是多路徑。來源中的數字：GPS.gov 簡報示意都市多路徑單點定位約 48.5 m vs 開闊地 2.3 m（未說明裝置）；PolyU 研究團隊稱以雙頻加 3D 地圖輔助可在香港都市峽谷達 5 m 內（該團隊自述）；Esri 論壇使用者稱雙頻手機實務上沒看過優於 3–5 m（軼事）；Google 2018 簡報稱當時手機 GNSS 皆為單頻 L1。
- 沒找到針對台北騎樓/老街的實測報告。
- `watchPosition`：MDN 只說「位置改變時呼叫」，沒有保證頻率；頻率依裝置與瀏覽器。選項 enableHighAccuracy / timeout / maximumAge。需要 HTTPS 與使用者授權。
- `coords.heading`：MDN 說當 speed 為 0 或裝置無法提供時為 null。heading 是移動方向（由 GPS 推算），靜止時無用。要靜止時的方向需 `DeviceOrientationEvent`：iOS 用 `webkitCompassHeading` 且 iOS 13+ 需在使用者手勢內呼叫 `requestPermission()`；Android Chrome 用 `deviceorientationabsolute`（此段是 WebFetch 摘要工具依一般知識補充，非 MDN 頁面明文，需驗證）。

對專案的影響：騎樓、窄巷誤差可能達數十公尺，「附近 20 公尺內的電線桿」這類精準觸發不可靠。

建議做法：
- 觸發半徑用 `coords.accuracy` 動態調整，精度差時改成講「這一帶」的泛用冷知識。
- 用最近 POI 前先做平滑（取最近幾筆、丟棄 accuracy 過大的點）。
- 方向用 heading（移動中）+ 羅盤（靜止）。
- Demo 用模擬散步模式作保底。

## 3. 手機網頁限制

### 3.1 自動播放音訊

發現：
- Chrome：有聲 autoplay 在「使用者與網域互動過」、或站點加到手機主畫面時允許；Web Audio 的 AudioContext 在手勢前為 suspended，手勢後 `resume()`，或在點擊事件內建立。
- iOS Safari：AudioContext 起始為 suspended，需使用者手勢內 resume。頁面隱藏（切 tab、切 App、鎖屏）時 Safari 會暫停 AudioContext，建議在 `visibilitychange` 時 resume 並提供「點擊繼續」的備案（來源為部落格，非官方）。
- WebKit bug：iOS 26 主畫面 web app 的 Web Audio 有只第一次執行可用的回報（bug 291892，使用者回報）；iOS 17.0 曾有背景暫停問題，17.1 起修正（bug 回報）。
- iOS 上 speechSynthesis 也須由使用者動作（點擊）觸發（來源為部落格）。

對專案的影響：「網頁在沒有點擊情況下主動出聲」不可行；必須有第一次點擊（例如「開始散步」按鈕）解鎖，之後同一個頁面內可持續播。

建議做法：
- 「開始散步」按鈕內：建立 AudioContext 或播放一小段靜音 `<audio>`，之後所有 TTS 用同一個 `<audio>` 元素/AudioContext 播放（推論：重複使用已解鎖的元素最穩）。
- 偵測 `audioContext.state`，被暫停時顯示大按鈕「點一下繼續導覽」。

### 3.2 螢幕鎖定、背景

發現：
- iOS：WebKit 舊 bug 指出螢幕關閉時 JS 被暫停，`ended` 事件不會觸發；獨立（主畫面）PWA 離開後音訊停止，而在 Safari 內播放離開 Safari 仍持續（2019 bug 回報、Discourse 討論，皆為使用者說法，且無 iOS 18 資料）。
- 定位：沒找到官方文件證實網頁在背景可持續 watchPosition。Apple 官方文件說明 iOS 會很快暫停背景 App，背景定位需原生 "Location updates" background mode（針對原生 App）。Capacitor 論壇回報 Android 背景後 watchPosition 不再回呼，需 foreground service；Chromium code review 評論稱頁面不可見時 geolocation 連線會關閉（皆為非官方）。
- 結論（推論）：網頁版**螢幕鎖定/背景後，定位與 JS 都不可靠**；最安全的設計是「螢幕保持亮著」。

### 3.3 Screen Wake Lock

- MDN 標示為 Baseline 2025（2025 年 3 月起新近可用）；Chrome 文件列 Safari 16.4 起支援。
- 要 HTTPS；頁面不可見、低電量、省電模式會被拒絕或釋放；釋放後需重新 request，建議在 `visibilitychange` 時重新取得。
- 主畫面 PWA 在 iOS 16.4～17.x 的回報不可用（WebKit bug 254545 使用者回報），現況無官方資料。

建議做法：在 Safari 瀏覽器內使用（不要求加到主畫面），按「開始散步」時 request wake lock，並做 feature detect 與失敗提示「請保持螢幕開啟」。

### 3.4 麥克風串流 getUserMedia → WebSocket

發現：
- iOS Safari MediaRecorder 在 18.4 之前只輸出 AAC MP4（audio/mp4），18.4 起新增 WebM、Ogg、fragmented MP4、無損（addpipe 部落格）。要用 `MediaRecorder.isTypeSupported()` 判斷。
- 2023 WebKit bug：iOS 15.6–16.2 的 AudioWorklet 收到的 PCM 速率比設定低（未確認是否修正）。
- 串流用途的來源很少。

建議做法（推論）：「按住說話」用 `AudioWorklet` 取 PCM、以實際 `audioContext.sampleRate` 重採樣成 16 kHz、經 WebSocket 傳；或更簡單：按住期間 MediaRecorder 錄整段，放開後一次上傳（延遲稍高但最穩）。黑客松推薦後者作為備案。注意 iOS 開麥克風時可能改變音訊路由（藍牙耳機可能降成通話音質，推論，未查到來源）。

### 3.5 Web Speech API（SpeechSynthesis）

發現：
- Chrome 的 voices 是非同步載入，需等 `voiceschanged`；線上時有額外聲音。
- iOS 的 zh-TW 聲音是 Mei-Jia（compact），可在「輔助使用 > 朗讀內容 > 聲音」下載 enhanced，使用者回報改善不一。
- 我沒找到日文/英文聲音品質的文件，也沒找到 Android zh-TW 聲音資料。

建議做法：SpeechSynthesis 只當離線/失敗備案，不當主要聲音（品質與聲音因裝置而異，使用者不可控）。

### 3.6 PWA vs 原生（Expo / React Native）

發現：
- Expo：iOS 背景定位在 Expo Go 不支援，需要 development build；需在 Info.plist 加 `location` 背景模式；iOS 要 "Always" 權限；Android 需前景與背景權限；使用者終止 App 後背景定位停止。expo-audio 背景播放的資料沒查到。
- iOS development build 需要 Apple Developer 帳號才能裝實機（我沒查來源，屬一般認知，推論）。

對專案的影響：原生可解背景定位與鎖屏音訊，但 4 天內要含建置、簽署、分發給評審，風險高；評審需要網頁連結即開的體驗。

建議：**做網頁版為主**（需求也寫優先網頁）；Demo 時要求螢幕常亮；背景/鎖屏運作列為「已知限制」並放進 pitch 的下一步。

## 5. 人臉模糊（瀏覽器端備案）

發現（官方 MediaPipe 文件）：
- `@mediapipe/tasks-vision` 的 Face Detector 可用於網頁；short-range 模型為 BlazeFace，輸入 128x128，針對手機前鏡頭自拍近距離；full-range（針對後鏡頭/遠距）在文件頁上標示 "Coming soon"（頁面時間點）。
- `detect()` / `detectForVideo()` 是同步呼叫，會阻塞主執行緒，建議放 Web Worker。預設 minDetectionConfidence 0.5。
- 舊的 `@mediapipe/face_detection` 已被導向新 Tasks API。

對專案的影響：路人通常距離較遠，short-range 模型對遠距小臉召回可能不佳（推論）。

建議做法：拍照流程為：照片 → MediaPipe 偵測（調低 minDetectionConfidence，如 0.3）→ 用 canvas 對每個框外擴約 30% 後做 blur/pixelate → 才送雲端/SAM。偵測失敗時的保守備案：可選項「模糊整張人物區」或讓使用者手動確認。要在實機測遠距街景照片。

## 6. 模擬散步模式

地圖元件：
- Leaflet：只吃 raster，記憶體少、簡單；MapLibre GL JS：向量圖磚、WebGL、手機流暢但吃資源（來源皆為廠商部落格，無獨立基準）。
- 建議 Leaflet（最快上手，4 天專案），除非要旋轉地圖/3D。

OSM 圖磚使用規範（OSMF 官方）：
- 沒有黑客松豁免；要 HTTPS、頁面要送 Referer、不可濾掉 Referer、顯示 OSM 姓名標示（右下、不可藏起來）。
- 遵守快取（最少 7 天）。
- **禁止預取/離線下載/批量下載**，只能抓當前視野圖磚。
- 大量使用可能被封，無 SLA；提到可改用社群列出的提供者、自架、向量圖磚。
- 推論：評審同時使用量小，Demo 用 tile.openstreetmap.org 應可，但請另備：換成 MapTiler/Stadia 等有免費層的服務（我沒查到它們的條款），或自行打包 PMTiles（沒查到來源，需再研究）。圖磚網址別寫死，方便切換。

模擬 GPS 軌跡（推論，無來源）：
- 預先做一條路線（OSM 道路或手畫折線 GeoJSON），以固定速度（如 1.2 m/s）沿折線內插，每秒產生一個「假 position」物件，格式與 `watchPosition` 的 `coords`（latitude/longitude/accuracy/heading）一致，餵給同一個觸發邏輯。
- 程式架構：把定位來源抽象成介面，真實 GPS 與模擬器共用同一份處理程式碼。
- 模擬模式下 heading 可由相鄰兩點計算。

## 最大技術風險 Top 5 與緩解方法

1. **網頁在背景/鎖屏後定位與音訊中斷**（iOS 最嚴重）。緩解：Demo 要求螢幕常亮 + Wake Lock；使用者介面提示；列為已知限制；不在 4 天內做原生。
2. **音訊解鎖與 iOS 版本怪癖**（AudioContext suspended、主畫面 web app 回報問題）。緩解：「開始散步」按鈕解鎖並重用同一元件；在 Safari 內跑而非加到主畫面；`visibilitychange` 後重新 resume 並有「點一下繼續」按鈕；實機測 iOS 與 Android。
3. **冷知識物件在 OSM 資料不足**（人孔蓋 151、檳榔攤 1、垃圾桶 680 等）。緩解：Demo 區域預選 POI 並補資料；通用情境式冷知識；拍照辨識作為補強。
4. **公用服務限制**（Overpass 約 100 query/天等同「regular use」、Nominatim 1 req/s、OSM 圖磚禁預取）。緩解：預先抓取靜態 POI JSON、行政區用本地 polygon、避開 Nominatim；圖磚網址可切換；避免部署在 Wiki 點名不建議的 netlify.app / lovable.app（Overpass 端，若有 server 端呼叫）。
5. **TTS 延遲與台灣腔/中英夾雜品質無可靠資料**；另外 **GPS 在騎樓誤差大**。緩解：預合成音檔；各家用實際講稿試聽；用 `accuracy` 動態調整觸發半徑；模擬散步模式作保底。

（人臉模糊遠距召回不足為次要風險：調低門檻、外擴框、實機測試。）

## 建議技術選型

- 前端：網頁（Safari / Chrome），HTTPS；Leaflet + OSM 圖磚（圖磚 URL 可切換）。
- 資料：預先抓取的台北 Demo 區域 OSM POI 靜態 JSON（build 階段用 Geofabrik extract 或一次性 Overpass）；行政區用 GeoJSON point-in-polygon；不使用 TDX 與 Nominatim。
- 定位：`watchPosition`（enableHighAccuracy）+ accuracy 過濾 + heading/羅盤；定位來源抽象，與模擬器共用。
- 音訊：點擊解鎖 + 單一 `<audio>`/AudioContext；Wake Lock；預合成 mp3 + 即時 TTS（Azure zh-TW 或 ElevenLabs，先試聽）；SpeechSynthesis 備案。
- 語音輸入：按住錄音，AudioWorklet/MediaRecorder 二擇一（先 MediaRecorder 整段上傳）。
- 人臉模糊：MediaPipe Face Detector（tasks-vision）+ canvas 模糊，作為 SAM 之前/備案。
- 不做原生；把背景定位/鎖屏音訊放在「下一步」。
